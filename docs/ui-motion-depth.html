Depth and motion, without losing the run.

Eight additions to the interface, each one live below — flip a switch and watch the phone. Every effect is built on the tokens already in src/styles.css, and every one is evaluated against the constraint the rest of this app is built around: it has to stay readable at arm's length, in sunlight, mid-run, on all three themes.

Your system is set to reduce motion, so the animations here are suppressed — which is exactly what the real implementation does. Switch the setting off if you want to see them move; the depth and transparency proposals still work either way.

Ready now

Six changes that are pure CSS, cost nothing at runtime, and touch no component logic. Together they are roughly ninety lines.

.btn:active · .run-item:active · .tabs button:active

Make every tap answer back

This is the gap I'd close first. Right now nothing in the app has an :active state except .metric-pod — buttons, history rows and tabs all sit perfectly still under a thumb. On a touch screen with no hover to fall back on, that reads as a dropped input, and the instinct is to tap again.

A 90 ms scale to 0.972 plus a brightness nudge fixes it. Note that the amount is a token, not a constant: Soft and Daylight compress, --press-scale: 1 keeps HUD rigid and lets it answer with brightness alone, because a springy button would contradict everything else that theme says. Daylight darkens instead of brightening — on white, "brighter" is invisible.

~14 linesno JSall themes
CSS 
.btn, .run-item, .tabs button {
  transition: transform 90ms ease-out, filter 90ms ease-out;
}
.btn:active, .run-item:active, .tabs button:active {
  transform: scale(var(--press-scale, 0.972));
  filter: brightness(1.14);
}
[data-theme='day'] .btn:active { filter: brightness(0.95); }
.screen-host[hidden] · @starting-style

Cross-fade between tabs

Tab changes are a hard cut today. A 190 ms fade with a 6 px rise tells you the screen replaced the last one rather than the last one having redrawn — worth more than it sounds when five tabs share a layout.

The reason this is cheap for you specifically: App.tsx keeps all five screens mounted and toggles the hidden attribute. That is a display change, which used to be unanimatable and needed a JS timing hack. transition-behavior: allow-discrete and @starting-style went cross-browser baseline this year, so it is now four lines and no JavaScript. Switch tabs in the preview to compare.

~10 linesno JSbaseline 2026
CSS 
.screen-host {
  transition: opacity 190ms ease-out, transform 190ms ease-out,
              display 190ms allow-discrete;
  opacity: 1;
}
.screen-host[hidden] { opacity: 0; transform: translateY(6px); }
@starting-style {
  .screen-host { opacity: 0; transform: translateY(6px); }
}
--shadow-1 · --shadow-2

An elevation ladder each theme controls

You asked about shades, and this is where they belong. .card has no shadow at all — surfaces are separated purely by a 1 px border, so everything sits on one plane.

The trap is a single global shadow. Try each theme with this on: Soft takes a soft ambient cast; HUD sets --shadow-1: none and stays flat, because a glow under a hard-edged instrument panel just looks like a mistake; and Daylight benefits most of all, trading its heavy #b3bfcc 2 px border for a crisp low-alpha shadow and a lighter line, which is the single biggest thing holding that theme back right now.

~12 linesno JSper-theme values
CSS 
[data-theme='soft'] {
  --shadow-1: 0 1px 2px rgba(0,0,0,.4), 0 10px 26px -14px rgba(0,0,0,.85);
}
[data-theme='hud'] { --shadow-1: none; }   /* deliberate */
[data-theme='day'] {
  --shadow-1: 0 1px 2px rgba(11,15,20,.07), 0 6px 16px -10px rgba(11,15,20,.35);
}
.card, .run-item { box-shadow: var(--shadow-1); }
.screen::after — new element

Let content fade out under the tab bar

The transparency you already have is the tab bar's blur(16px). The problem is what happens at its top edge: content slides under a hard line and is simply guillotined. Scroll the preview with this off, then on.

A 92 px gradient scrim from var(--bg) to transparent makes content dissolve instead of getting cut, which reads as depth and — more usefully — signals that there is more below. It's also the honest fix for a real bug: with a floating bar and --tab-inset: 10px, Soft currently shows a sliver of live content in the gap beneath the bar.

~8 linesno JSfixes a clip
CSS 
.screen-host::after {
  content: '';
  position: fixed; left: 0; right: 0; bottom: 0; height: 92px;
  pointer-events: none; z-index: 19;
  background: linear-gradient(to top,
    var(--bg) 26%,
    color-mix(in srgb, var(--bg) 55%, transparent) 62%,
    transparent);
}
.live-hr-pill · --zone-1..5

Tint the heart-rate pill with its own zone

You already have a five-rung colour ladder that is per-theme and contrast-checked, and it is currently only used in charts and the history strip. The live HR pill — the thing you actually glance at while running — is neutral grey.

Tinting its background, border and a soft outer halo from --zone-N means zone becomes readable peripherally, without focusing on the number. The 500 ms transition matters: zone crossings should drift, not snap, or a heart rate hovering on a boundary makes the pill strobe. Reusing the existing tokens means Daylight gets its darker ladder for free.

~9 lines1 line TSXreuses --zone-N
CSS + the one JS change 
/* RunScreen sets style={{ '--z': zoneSwatch(zone) }} on the pill */
.live-hr-pill {
  border-color: color-mix(in srgb, var(--z) 55%, transparent);
  background:   color-mix(in srgb, var(--z) 13%, var(--surface-2));
  box-shadow: 0 0 18px -4px color-mix(in srgb, var(--z) 60%, transparent);
  transition: box-shadow 500ms ease-out, background-color 500ms ease-out,
              border-color 500ms ease-out;
}
.metric.dist

Mark the kilometre, ignore the second

The restraint is the whole proposal. The obvious move is animating numbers as they change, but your clock ticks once a second for an hour — animate that and you have built a distraction you cannot switch off.

So: animate nothing on tick, and flash the distance for 620 ms only when the whole-km digit rolls over. That's a real event worth reporting, it happens roughly every five minutes, and it pairs with the split you already log. Turn it on and press the button.

~10 lines1 line TSXevent-gated
CSS 
@keyframes km-tick {
  0%   { transform: scale(1);    color: var(--text); }
  22%  { transform: scale(1.07); color: var(--accent); }
  100% { transform: scale(1);    color: var(--text); }
}
.metric.dist.ticked .value {
  display: inline-block;
  animation: km-tick 620ms cubic-bezier(.2,.7,.3,1);
}

Bigger lift

Both are the genuinely current techniques, and both are worth doing — but they touch markup and component structure, so they're separate decisions.

animation-timeline: scroll()

Condense the header as you scroll

Every screen spends 26 px of vertical space on an h1 and a subtitle that stop being useful the moment you start reading. Turn this on and scroll the preview: the title shrinks to 72%, the subtitle fades, and a blurred bar picks up behind it — the same material as the tab bar, so the chrome bookends the content.

The notable part is that this is scroll-linked with zero JavaScript. No listener, no IntersectionObserver, no re-render — it runs on the compositor, which is why it holds 60 fps on a phone. scroll() and view() reached cross-browser baseline this year. It needs the heading wrapped in a sticky element on each screen, which is the actual cost.

markup changeno JS×5 screens
CSS 
@supports (animation-timeline: scroll()) {
  .screen-head {
    position: sticky; top: 0; z-index: 3;
    animation: head-condense linear both;
    animation-timeline: scroll(nearest);
    animation-range: 0 90px;
  }
  @keyframes head-condense {
    to {
      font-size: .72em;
      background: color-mix(in srgb, var(--bg) 82%, transparent);
      backdrop-filter: blur(12px);
      box-shadow: 0 1px 0 var(--line-soft);
    }
  }
}
document.startViewTransition()

Morph a history row into its run

Turn this on, go to History in the preview, and tap a run. The route thumbnail and the headline fly from the row into the detail screen rather than the whole view being swapped out — so the run you chose is visibly the run you are now looking at.

This is the one that most changes how the app feels, and it is also the one with a real prerequisite: history rows need route thumbnails, which don't exist yet. That's a small RouteMap variant rendering a simplified polyline with no tiles — worth building on its own merits, since it turns a list of numbers into something scannable. Then the transition is about fifteen lines.

Browser support is less of a caveat than it used to be for you: the Capacitor Android shell runs on Chromium, so the installed app always gets this. Desktop Firefox falls back to a plain cut — which is exactly today's behaviour, so nothing regresses.

needs thumbnails~15 lines JSgraceful fallback
The pattern 
function openRun(id) {
  if (!document.startViewTransition) return setDetail(id);  // Firefox
  document.startViewTransition(() => flushSync(() => setDetail(id)));
}

/* the two shared elements, named identically on both screens */
.run-item[data-open] .thumb,
.detail .route      { view-transition-name: run-thumb; }
.run-item[data-open] .headline,
.detail h1          { view-transition-name: run-title; }

One thing to fix regardless

prefers-reduced-motion is honoured in exactly one place in the stylesheet — .dot.live. Three animations are already running past it: goal-pulse, live-rec-pulse and pulse, the last of which loops forever. Before adding anything above, the gate should be a blanket rule rather than per-animation opt-in, so new motion is covered by default instead of being remembered. 

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .001ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .001ms !important;
    scroll-behavior: auto !important;
  }
}

If you only take three: press response, the elevation ladder, and the scrim. Those are the ones people read as "modern" without being able to name why, they are about thirty lines between them, and none of them moves anything while you are trying to read a number at running pace.

  • :activeRemoves the dropped-input feeling. Biggest gain per line in the whole list.
  • --shadow-1Gives Daylight a way off its heavy border, and gives every theme a second plane.
  • scrimStops content being guillotined by the tab bar, and closes the sliver under it.
